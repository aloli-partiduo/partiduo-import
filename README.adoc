= partiduo-import — import d'opérations en masse
:toc: left
:toc-title: Table des matières
:icons: font

*Partiduo* est le portage en Crystal de https://noalyss.eu[NOALYSS], logiciel
libre de comptabilité créé et maintenu par *Dany De Bontridder*. Partiduo
n'est pas un projet officiel NOALYSS.

Ce dépôt est l'extension `IMPORT` de Partiduo (ADR-003, table « Sort des
extensions amont »), successeur de l'import avancé de NOALYSS
(`advancedimport`, IMPOP2) et de la correspondance des codes de TVA de
`noalyss-plugins/import_account` (D-OUT-001 du cœur) — la source *legacy* :
on en porte les fonctions, pas le code. Des écritures de *tous les types de
journaux* — achats, ventes, financiers, opérations diverses — sont lues dans
un CSV au format enregistré ou dans un *fichier des écritures comptables*
(FEC, article A47 A-1 du LPF), essayées à blanc par le service d'écriture de
la Comptabilité, mises en attente avec les motifs de leurs refus, puis
transférées sur votre décision, avec la numérotation du cœur et le fichier
source en pièce jointe.

Spécification : `../partiduo-docs/adr/ADR-003-contrat-extensions.adoc`, avec
ADR-005 (interface), ADR-006 (Comptabilité) et ADR-011 (dossier foyer).
Décisions (`D-IMP-*`), inventaire des fonctions legacy et amendements
proposés : link:DECISIONS.adoc[]. Référence du contrat :
link:doc/api/import.adoc[].

== Fonctions

[cols="1,3",options="header"]
|===
|Fonction |Dans IMPORT

|Formats CSV enregistrés
|Genre de journal, séparateur, délimiteur de texte, encodage (UTF-8,
Windows-1252, ISO 8859-15), lignes d'en-tête, format de date (les huit de
l'application d'origine), séparateurs décimal et de milliers, rang de la
colonne de chaque champ (date, journal, regroupement, pièce, libellé,
devise, échéance, tiers, compte ou fiche, libellé de ligne, montant, sens,
débit, crédit, quantité, code et montant de TVA, toutes taxes, postes
analytiques). Code de TVA admis en opérations diverses, postes
analytiques en financier.

|FEC
|Lu par le lecteur commun du cœur (`Accounting.read_fec`) : zones lues par
leur nom, tabulation, barre verticale ou point-virgule, encodage reconnu ;
une écriture par journal et numéro d'écriture ; comptes auxiliaires vers
les fiches ; comptes absents du plan créés *un par un, sur demande* ;
taux et rôles de TVA d'une facture d'achat ou de vente retrouvés par les
comptes de TVA du dossier et les montants (facture déclarable) ; reprise
du lettrage (`EcritureLet`) ; écriture déjà reprise par
`partiduo-migrate` signalée.

|Correspondances
|Journaux, codes de TVA, comptes et fiches de l'émetteur vers ceux du
dossier ; codes inconnus des opérations à traiter listés et complétés sur
place.

|Aperçu à blanc et zone d'attente
|Chaque opération est passée *réellement* par le service d'écriture dans
`Partiduo::Api::Transaction.dry_run`, puis tout est annulé : pièce que le
cœur donnerait, ou motifs du refus (écriture déséquilibrée, période close,
compte inconnu…). Rien ne passe d'office.

|Doublons
|Opération déjà importée (empreinte, occurrences comptées), fichier déjà
importé, écriture semblable déjà passée hors de l'extension.

|Transfert
|Une écriture par opération par `post_entry`, `post_purchase`, `post_sale`
ou `post_financial` (variantes ventilées de l'analytique, extrait
financier compris), avec l'acteur réel ; numérotation du cœur, pièce de
l'émetteur gardée en référence de l'écriture ; refus gardés sur
l'opération ; extourne rendue à traiter (`entry.cancelled`).

|Historique
|Imports, compteurs, anomalies de lecture, fichier d'origine
téléchargeable, suppression d'un import non transféré.
|===

La *reprise intégrale* d'un dossier venu d'un autre logiciel dans une
instance neuve (plan, journaux, exercices, fiches, rapport de
réconciliation au centime) reste l'affaire de `partiduo-migrate` ; l'import
d'un FEC ici complète un dossier *existant* (D-IMP-011).

[source]
----
src/
├── partiduo-import.cr          # point d'entrée du shard
├── partiduo-import/cli.cr      # migrations : require "partiduo-import/cli"
└── import/                     # métier (application Marten « import »)
    ├── app.cr, manifest.cr     # code IMPORT, permissions, menus, abonnement
    ├── models/                 # tables import_*
    ├── migrations/             # 0001 : tables et contraintes
    ├── parsers/                # CSV, FEC lu par le cœur, montants, dates, encodages, champs
    ├── services/               # correspondances, TVA d'un FEC, essai à blanc, doublons, transfert, lettrage
    ├── api/                    # contrat public Import::Api
    └── locales/                # fr, en, nl, de, es, it, pt
ui/
└── bulma/                      # interface pour partiduo-ui-bulma (application « import_ui »)
    ├── bulma.cr                # routes sous /ext/IMPORT/, compteur du menu
    ├── dashboard_tile.cr       # tuile « Opérations importées »
    ├── handlers/, templates/import/, assets/import/, locales/
spec/fixtures/                  # CSV d'opérations diverses, d'achats, de banque ; FEC
----

== Composer une distribution

[source,crystal]
----
require "partiduo-ui-bulma/partiduo_ui"
require "partiduo-import"
require "partiduo-import/ui/bulma"
# installed_apps += Import::INSTALLED_APPS + Import::Ui::INSTALLED_APPS
# ligne de commande : require "partiduo-import/cli"
----

L'extension exige la Comptabilité (`depends_on "ACCOUNTING"`) ; elle
s'active par dossier (`Partiduo::Api::Modules.activate`, écran « Modules »),
dossier foyer compris. Elle emploie le contrat 0.14.0 du cœur au moins
(`read_fec`, `external_reference`, `EntryLineInput#vat_rate`,
`Analytic.post_financial`) : cœur 0.1.30 ou suivant.

== Développement local

`shard.yml` et `shard.lock` référencent les shards maison sur GitHub
(`aloli-crystal/*` et `aloli-partiduo/*`), suivis par branche. Le verrou
versionné ne contient aucune dépendance `path:` : les ports FreeBSD et la CI
l'exigent.

Pour travailler sur les copies de travail voisines (`../../prod-crystal/<nom>`
et `../partiduo-<dépôt>`), lancer :

[source,sh]
----
scripts/override-local.sh
----

Le script génère un `shard.override.yml` *local et non versionné* (ignoré par
git), installe les shards, puis remet `shard.lock` à son état versionné.
Une copie de travail absente reste prise sur GitHub.

Pour régénérer le verrou versionné, supprimer d'abord l'override local :

[source,sh]
----
rm -f shard.override.yml
SKIP_MARTEN_CLI_PRECOMPILATION=1 shards update
scripts/override-local.sh   # retour au mode local
----
